# 导读：学会沿着边界追问

你也许已经用过 Linux 很多年：部署服务、启动容器、挂载目录、调整进程参数。真正让人困惑的，往往不是某条命令怎么写，而是为什么几种看起来毫不相关的工具，最后总能接在一起。

一个通过 SSH 访问的远程目录，为什么能像本地目录一样被编辑器打开？一份容器镜像，为什么能被很多容器共享，却允许各自修改文件？Mac 明明运行着自己的操作系统，又怎样运行 Linux 容器？把 x86 指令翻译成 ARM 指令，为什么还不等于把一个程序完整移植过去？

本书从这些疑问出发。它不把 Linux 写成一个需要背诵的特性清单，而把它看成一组边界明确、可以组合的机制。你会先认识谁负责执行、谁管理地址、谁提供接口，再看到文件系统、容器和虚拟机怎样建立在这些基础上。到最后，你应该能够沿着一项请求往下追，而不仅是记住最上面那个工具的名字。

## 为已经会写软件的人补一张地图

本书假定你知道程序、函数、线程、文件和网络的大致含义，能读少量命令或伪代码。不要求你会写驱动，也不要求你先学完操作系统教材。涉及页表、虚拟机退出或文件对象时，重点是它们为什么存在、解决了什么冲突、引入了什么成本；不展开几百行结构体，也不以寄存器清单代替理解。

我们采用三种尺度。第一种是机制：例如一个文件描述符究竟指向什么。第二种是组合：例如运行时怎样用多个机制构造容器。第三种是边界：例如这套组合为什么不能直接把 Linux 内核换成 macOS 内核。三种尺度相互校正，避免只懂抽象，也避免陷入实现枝节。

## 怎样判断一句话值不值得相信

书中事实说明附近的链接，是这一段的证据入口，而不是装饰。涉及 Linux 行为，优先读内核文档和 Linux man-pages；涉及 QEMU、OCI、Android、Apple 等平台，则读项目自己的文档或源码。社区对闭源平台的研究会明确标注身份。资料核查基准日为 **2026-10-22**，不是对今后所有版本的保证。

“为了理解，可以把它看作……”引入的是教学模型。图中的方框表示职责或对象，不表示它们一定一对一对应进程；箭头表示本图指定的关系，不代表精确时序、调用次数或性能比例。封面是 AI 生成概念插画，正文章的机制图由程序绘制，均不能替代旁边的原始资料。

文中观察命令没有附带伪造的终端结果。每一台机器的内核、权限和工具版本都会改变输出；你应该观察关系是否成立，而不是追求复制某个数字。部分章节列出需要额外安装的工具，未安装或权限不足属于观察环境条件，不是机制失效。

## 读完以后应该能做什么

你应当能解释：进程在 CPU 空闲时为什么仍然很慢；删除名字为什么未必立即释放文件空间；内存占用为什么不能简单相加；FUSE 与 OverlayFS 为什么不是同一类“虚拟文件系统”；容器与虚拟机各自把边界放在哪里；KVM 与 QEMU 为什么经常一起出现；Android 与 macOS 为什么不能仅用“类 Unix”三个字概括。

这些目标不要求你成为每个子系统的维护者。它们要求的是：面对一个新特性，先问它放在哪一层、接管了什么、保留了什么、失败时影响到哪里，再去看产品名称和配置选项。能够提出这几个问题，就已经建立了继续学习的支点。

按顺序阅读是最稳的路线。已有兴趣也可以跳到 FUSE、KVM 或 Android，但遇到“打开状态”“地址空间”“系统调用”等词时，请回到对应基础章。附录提供反向索引，全书的源文件顺序由 `book.json` 维护，便于今后直接构建在线阅读站。
