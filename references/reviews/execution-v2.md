## 确证问题

### EX-01：动态链接后的图标签把程序入口与进程存在混在一起

- **严重度：低（图示精度，应修订）。**
- **位置：** 第 05 章图 5-1，对应 `assets/images/05-abi.svg`；生成器中的同名图也需同步。
- **原文短引：** “加载与动态链接”之后的方框写“进程开始运行”。
- **事实问题：** 动态加载器已在同一个进程中执行。`execve` 替换程序映像，不创建新进程；因此把“进程开始运行”放在动态链接完成之后，会让读者误以为加载器阶段尚无正在执行的进程。正文 3.2 与 5.2 本身表述基本正确，问题局限于图的标签。
- **原始来源：** [execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html) 的进程映像替换与 ELF 解释器说明；[ld.so(8)](https://man7.org/linux/man-pages/man8/ld.so.8.html) 的 DESCRIPTION 说明加载器准备并转入程序执行。
- **建议最小修订：** 标签改成“进入目标程序入口”或“目标程序开始执行”；保留图注关于动态/静态链接路线与简化模型的限制。不要改成“创建新进程”，也不必添加完整 ELF 初始化函数时序。

## 非错误的边界补充建议

### EX-S01：补明多线程程序 fork 的线程边界

- **严重度：建议补充，非原文明确事实错误。**
- **位置：** 第 03 章 3.2，fork 段后。
- **原文短引：** “fork() 创建子进程，父子从调用处继续”。
- **为什么值得补充：** 本章刚刚讲完多线程，技术读者容易顺势把整个线程集合也纳入“复制”。在子进程中只保留调用 fork 的线程，继承内存中的同步对象状态；这解释了一类看似神秘的等待，属于高信息量边界而非枝节。
- **原始来源：** [fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)，DESCRIPTION 中的 multithreaded program 说明，明确子进程只有调用线程，并列出 exec 前调用限制。
- **建议最小补充：** “若父进程有多个线程，子进程只保留调用 fork 的那个线程；内存中的锁状态却会被继承，因此多线程程序不能把 fork 后的子进程当成原线程集合的完整副本。”若进一步讨论 exec 前可调用函数，应照原手册加上异步信号安全限制，避免给出随意调用库函数的示例。

### EX-S02：给 initramfs 的真实根移交加上常见情形限定

- **严重度：建议补充，当前主线情境成立。**
- **位置：** 第 02 章 2.2，说明 `/init` 的段落。
- **原文短引：** “该程序准备最终根目录，并把运行环境移交给真正的系统”。
- **为什么值得补充：** 这解释了常见发行版的启动方式，但 initramfs 也可以承载最终用户环境，不必另有持久化真实根。正文已有‘常见而非强制阶段’图注，因而不构成章节主要错误。
- **原始来源：** [Ramfs, rootfs and initramfs](https://docs.kernel.org/filesystems/ramfs-rootfs-initramfs.html)，What is initramfs 一节对 real root device 使用“if any”限定。
- **建议最小修订：** 在移交说明前加“在常见发行版的启动路线中”，或补“也可直接把 initramfs 作为最终用户环境”。无须展开所有嵌入式启动路线。
